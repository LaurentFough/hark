# This fork and its upstreams

`LaurentFough/hark` is the canonical repository for this fork. It started as a
fork of [`konradk/hark`](https://github.com/konradk/hark) and adds
configurable OpenAI-compatible providers (originally from
[`xmmanuellx/hark`](https://github.com/xmmanuellx/hark)), loopback providers
without an API key, an Omarchy `__sourceDir` fix, and a single-repository
install (`scripts/install-omarchy.sh`).

## Remotes

| Remote        | Purpose                                   | Push |
|---------------|-------------------------------------------|------|
| `origin`      | `LaurentFough/hark`, the canonical repo   | yes  |
| `konradk`     | upstream source, read-only                | disabled |
| `xmmanuellx`  | fork that contributed providers, read-only | disabled |

```bash
git remote add konradk    https://github.com/konradk/hark.git
git remote add xmmanuellx https://github.com/xmmanuellx/hark.git
git remote set-url --push konradk    DISABLED
git remote set-url --push xmmanuellx DISABLED
```

## Taking changes from upstream

Look at upstream only when there is something worth having:

```bash
git fetch konradk --tags
git tag --list 'v*' --sort=-v:refname | head        # new upstream releases
git log --oneline main..konradk/main                # commits we do not have
git diff main...konradk/main --stat                 # what they touch
```

Then either merge everything (`git merge konradk/main`) or take individual
commits (`git cherry-pick <sha>`). The histories are related, so merges are
ordinary three-way merges. Run `go test ./...` before pushing.

## Why `konradk/hark-plugin` is not merged in

`konradk/hark-plugin` is generated by upstream's release workflow. Every commit
is a `github-actions[bot]` snapshot of a release: the QML from `konradk/hark`
plus prebuilt `bin/harkd` and `bin/harkctl`. Its QML is byte-identical to the
source at the matching tag (only the `manifest.json` version string and README
differ), so it carries no information that is not already here. Importing it
would add about 15 MB of binaries per release to the history and an
unrelated-history merge that conflicts on every release.

Releases are detected from the tags on `konradk/hark`. `scripts/install-omarchy.sh`
builds the runtime from this repository instead of consuming published binaries.
The upstream packaging scripts are kept unchanged so merges from upstream stay
conflict-free.
